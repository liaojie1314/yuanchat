# v0.4 / v0.5 — 社交扩展与实时通话（milestone outline）

> 立项：2026-07-31（v0.3.0 发布后）。v1.0 路线图 19/21 批次已完成
> （D2 iOS、D1 付费 OS 签名按决策跳过），本文档规划下一阶段。
>
> **约束**：继承全局约束（GitFlow `feature/*` → dev squash、i18n 四语言无硬编码、
> `build.target=es2019`（Chrome 74 WebView）、圆角上限 `rounded-lg`、
> 批次末尾门禁 + squash、**推 CI 前先本地打包验证**、app 内 import 的包必须在该
> app 的 package.json 声明）。
>
> 执行方式：每个批次开工前用 `superpowers:writing-plans` 展开为 TDD-step 级可执行
> plan，确认后再动代码。

## 里程碑划分（建议两个发布点）

| 版本   | 主题            | 批次                   | 预计工时 | 说明                     |
| ------ | --------------- | ---------------------- | -------- | ------------------------ |
| v0.4.0 | 体验补全 + 社交 | A6 + A7 + H1 + G1 + G2 | 4 周     | 风险低、可增量验收       |
| v0.5.0 | 实时通话        | F0 + F1 + F2           | 3-4 周   | 技术风险最高，spike 先行 |

> 放最后但用 F0 提前排雷。顺序可按需调整，批次间除标注外无硬依赖。

## A. 功能补齐（续 v1.0 的 A 系列）

### A6 — 会话置顶 + 免打扰完善（3-4 天）

- **目标**：会话可置顶排序；免打扰全链路（现状：`conversation_members.is_muted`
  字段与通知过滤已存在，缺 REST 开关与 UI）。
- **产物**
  - 迁移 009：`conversation_members` 加 `is_pinned bool` + `pinned_at timestamptz`。
  - 后端：`PUT /conversations/:id/settings`（body `{is_pinned?, is_muted?}`，
    member 维度）；WS `conversation.updated` 同步同账号其他设备。
  - 前端：会话列表排序（置顶按 pinned_at 倒序优先，其余按最新消息）；
    会话项右键/长按菜单 + 聊天设置页开关；置顶角标、免打扰铃铛斜杠图标；
    免打扰会话未读数灰显（不推系统通知——通知过滤已有，验证即可）。
- **验收**：集成测 settings 端点权限（非成员 403）；E2E：置顶后列表排序变化、
  免打扰后来消息无系统通知但未读数增加；多端同步（第二个登录实例收到 WS 帧）。
- **依赖**：无。

### A7 — 聊天体验补全（4-5 天）

- **目标**：清空聊天记录、群公告、群内昵称。
- **产物**
  - 迁移 010：`conversation_members` 加 `cleared_before_seq bigint`（单侧清空，
    拉历史时过滤 seq ≤ 该值）、`alias varchar(30)`（群内昵称）；
    `conversations` 加 `announcement text` + `announcement_updated_at`。
  - 后端：`POST /conversations/:id/clear-history`；`PUT /conversations/:id/announcement`
    （群主/管理员）；`PUT /conversations/:id/my-alias`；公告变更发系统消息 + WS。
  - 前端：聊天设置页「清空聊天记录」（确认弹窗）；群公告编辑 + 会话顶部横幅
    （新公告未读时展示，点开全文）；群内昵称编辑，气泡署名优先 alias。
- **验收**：清空后本人拉不到历史、对方不受影响；公告仅管理员可编辑（普通成员 403）；
  alias 在群消息气泡与成员列表生效、单聊不受影响。
- **依赖**：无（与 A6 同分支或相邻分支均可）。

## H. 表情服务

### H1 — 表情收藏 + 表情包（1 周）

- **目标**：自定义表情收藏（微信「添加到表情」式）+ 官方表情包，扩展现有
  EmojiPicker（`packages/ui/src/EmojiPicker.tsx`，现为原生 emoji + 最近使用）。
- **产物**
  - 迁移 011：`sticker_packs(id, name, cover_url, is_official, sort)`、
    `stickers(id, pack_id nullable, owner_id nullable, object_key, width, height,
content_hash unique-per-owner)`。官方包 seed 1-2 套（静态资源入 MinIO）。
  - 后端：`GET /stickers/mine`、`POST /stickers`（从已有图片消息 object_key 收藏
    或直传，hash 去重）、`DELETE /stickers/:id`、`GET /sticker-packs`。
  - 消息：**决策点 H1-a**（见下）——新 `MessageTypeSticker=8` 或复用 image 加
    `content.sticker=true` 标记。渲染：无气泡内边距、固定上限尺寸、不进图片
    lightbox 浏览流。
  - 前端：图片气泡菜单「添加到表情」；EmojiPicker 加 tab（emoji / 收藏 / 官方包），
    收藏 tab 内长按删除；发送即所见（乐观插入）。
- **验收**：收藏 → picker 出现 → 发送 → 双端渲染为贴纸样式；hash 去重（重复收藏
  不新增）；搜索/审核对贴纸消息的处理与图片一致。
- **依赖**：无。

## G. 朋友圈

### G1 — 朋友圈后端（1 周）

- **目标**：发布/信息流/点赞/评论闭环，服务端数据模型与权限。
- **产物**
  - 迁移 012：`moments_posts(id, user_id, content, images jsonb, created_at,
deleted_at)`、`moments_likes(post_id, user_id, created_at, uniq)`、
    `moments_comments(id, post_id, user_id, reply_to_user_id nullable, content,
created_at, deleted_at)`、`moments_activities(id, user_id 被通知人, actor_id,
post_id, kind like|comment, created_at, read_at)`（红点/消息列表）。
  - REST：`POST /moments`（文本 + ≤9 图，复用 MinIO 直传）、`GET /moments/feed?cursor=`
    （本人 + 好友，created_at 游标）、`GET /moments/user/:id`（好友校验）、
    `DELETE /moments/:id`（本人）、`POST/DELETE /moments/:id/like`、
    `POST /moments/:id/comments`、`DELETE /moments/comments/:id`、
    `GET /moments/activities`（未读互动）。
  - WS：`moments.activity` 推给被点赞/评论人（在线时红点实时）。
  - 审核接入：内容过敏感词打标管线（E3），admin 后台可删帖（复用 admin middleware，
    加 moments 审计页最小版）。
  - **决策点 G1-a**：评论可见性——v1 简化为「能看到帖子的人都能看到全部点赞/评论」
    （微信的"仅共同好友可见"逻辑复杂，v1.2 再议）。
- **验收**：集成测——非好友拉不到 feed/主页；删帖后 feed 消失且互动级联不可见;
  点赞幂等；activities 未读计数正确。
- **依赖**：无。

### G2 — 朋友圈前端三端（1 周）

- **目标**：feed / 发布 / 互动 / 红点全 UI，三端响应式。
- **产物**
  - 导航：侧栏（桌面）/ 底栏（移动）加「朋友圈」入口 + 未读互动红点。
  - 页面：信息流（头像 + 昵称 + 文本折叠 + 九宫格图 + 时间 + 点赞/评论操作条，
    游标分页 + 骨架屏）；发布页（文本 + 图片选择 ≤9、上传进度）；
    互动消息页（activities 列表，点击跳原帖）；个人主页帖子列表。
  - 复用：图片 lightbox、头像组件、时间格式化（`Intl` 四语言验证）。
  - i18n：全部文案四语言；空态/加载/失败态齐全。
- **验收**：E2E——A 发帖 → 好友 B 的 feed 可见 → B 点赞评论 → A 红点 + 互动页
  可见 → A 删帖 → B feed 消失；移动端九宫格布局、图片懒加载（复用 C2 模式）。
- **依赖**：G1。

## F. 实时通话

### F0 — WebRTC 跨端可行性 spike（1-2 天，可提前并行）

- **目标**：写一个最小 getUserMedia + RTCPeerConnection 回环 demo 页，逐端验证，
  排除平台级阻塞后再投入 F1。
- **验证矩阵与已知风险**
  | 端 | WebView | 预期 | 风险 |
  | --- | --- | --- | --- |
  | Web Chrome/Edge | — | ✅ | 无（需 HTTPS/localhost） |
  | Windows 桌面 | WebView2(Chromium) | ✅ | 低 |
  | macOS 桌面 | WKWebView | ✅ | 低（Safari 11+ 支持） |
  | **Linux 桌面** | webkit2gtk 4.1 | ⚠️ | WebRTC 为实验特性，可能需 enable 或记录为不支持 |
  | **Android** | 系统 WebView | ⚠️ | getUserMedia 需原生层转发权限（RECORD_AUDIO/CAMERA manifest + onPermissionRequest），Tauri 2 wry 是否转发待验证 |
- **产物**：`docs/superpowers/plans/` 附 spike 结论表；Android 需要的 manifest
  权限与 Tauri 配置改动清单；Linux 不可行时在 UI 层按平台隐藏通话按钮的方案。
- **验收**：明确每端「可用 / 需改动 / 不支持」结论，阻塞项有对策再开 F1。

### F1 — 1v1 语音通话（2 周）

- **目标**：好友间语音通话全流程（呼出/振铃/接听/拒绝/挂断/超时/占线）。
- **产物**
  - 信令（WS 新帧组）：`call.invite / call.ringing / call.accept / call.reject /
call.hangup / call.cancel / call.sdp / call.ice`；服务端中转 + Redis 记录
    通话态（occupied 检测、60s 无应答超时、断线清理）。
  - TURN/STUN：`deploy/docker-compose.prod.yml` 加 coturn（3478/udp+tcp，
    relay 端口段；**端口需避开 yuanai 占用，部署时确认**）；
    `GET /calls/turn-credentials` 用共享密钥签发临时凭据（TTL 1h）。
  - 前端：`packages/shared/src/webrtc/` 封装（PeerConnection 生命周期、ICE
    重连、设备枚举）；全局来电弹层（铃声 + 接/拒）；通话中浮条（时长、静音、
    免提、挂断）；权限拒绝/设备缺失的降级提示。
  - 通话记录：会话内系统消息（已接时长 / 未接 / 已拒绝），未接来电计入未读。
  - 平台门控：按 F0 结论对不支持端隐藏入口。
- **验收**：双真实客户端 REST+WS 验收（同 D4 模式）——A 呼 B 接听双向可听、
  拒绝/超时/占线/中途断网挂断各分支；TURN-only 网络（禁 P2P）可通；
  通话记录消息正确。
- **验收环境说明**：媒体流人工双端验证（自动化仅覆盖信令状态机单测/集成测）。
- **依赖**：F0。

### F2 — 视频通话（1 周）

- **目标**：F1 基础上加视频轨。
- **产物**：呼叫时选语音/视频；通话中开/关摄像头、前后摄切换（移动端）、
  本地画中画 + 远端全屏、横竖屏适配；语音↔视频升级降级（renegotiation）。
- **验收**：双端视频互通；关摄像头退化为语音不断线；移动端切摄像头生效。
- **依赖**：F1。
