# v0.3.0 实施计划：消息搜索 + 前端性能 + 后端可观测

> **状态：outline（milestone spec）**
> 详细 TDD 步骤在 v0.2.0 完成后、临近执行时用 `superpowers:writing-plans` 展开。此文档作为规划约束书 + 分工基线。

**Goal:** 补齐消息全文搜索、消息列表虚拟滚动、首屏 code-splitting，同时打通后端 Prometheus 指标 + Playwright E2E 上 CI。

**Architecture:** 搜索走 PG `pg_trgm` GIN 索引起步（无需 ES 依赖）；虚拟滚动用 `@tanstack/react-virtual`；code-split 走 Vite `React.lazy`；Prometheus 走 `prometheus/client_golang` Gin middleware；E2E 用 docker-compose 启动完整后端栈跑 Playwright。

**Tech Stack:** Go 1.25 / Gin / GORM / PostgreSQL 16 + `pg_trgm`；React 19 + `@tanstack/react-virtual`；`prometheus/client_golang` + Grafana Cloud/自托管；Playwright + docker-compose。

## Global Constraints（继承 v0.2.0）

- 分支 `feature/v0.3-search-perf-observability`
- Go 工具链、集成测试、i18n、图标、圆角、surface、zustand 规范全部继承
- 每批次末尾门禁 + squash + `pnpm dev:stop`
- 新增：搜索接口必须支持中文分词（trigram + `simple` 配置）；Prometheus `/metrics` 走独立端口 `:8082`，不暴露业务网络

## 里程碑批次

### 批次 1（A4）：消息全文搜索（1 周）

**新增文件（关键）：**

- `server/migrations/2026xxxx_add_pg_trgm.sql`（`CREATE EXTENSION IF NOT EXISTS pg_trgm; CREATE INDEX idx_messages_content_trgm ON messages USING gin (content gin_trgm_ops);`）
- `server/internal/handler/search.go`
- `server/internal/service/search_service.go`
- `packages/shared/src/api/search.ts`
- `packages/ui/src/GlobalSearchModal.tsx`（Ctrl/Cmd+K 唤起）
- `packages/ui/src/ConversationSearchSidebar.tsx`

**REST 端点：**

- `GET /messages/search?q=&conversationId=&cursor=&limit=` → `{items:[{message, conversationId, previewHtml, matchOffsets}], nextCursor}`
- `GET /search?q=&limit=` → `{contacts:[], groups:[], messages:[]}`（聚合搜索）

**验收：**

- 中文关键词命中；单元测试覆盖 trigram 相似度阈值（默认 0.3）
- E2E：Ctrl+K → 搜「照片」→ 命中 → 点击跳转 + 高亮 3 秒

**依赖：**

- 前置：无（可与 E1 DB migrate 并行；本批次自带迁移文件）

### 批次 2（C1）：消息列表虚拟滚动（1 周）

**改动关键文件：**

- `packages/ui/src/ChatMessages.tsx`（引入 `useVirtualizer`）
- `packages/shared/src/store/messageStore.ts`（保持接口稳定，virtual 只在渲染层用）

### 批次 4（B2）：Prometheus 指标 + Grafana 看板（3 天）

**新增文件：**

- `server/internal/observability/metrics.go`
- `server/internal/router/router.go` 增 middleware
- `server/cmd/server/main.go` 启 `:8082` metrics 端口
- `docs/observability/grafana-dashboard.json`
- `docs/observability/README.md`

**关键指标：**

- `http_request_duration_seconds{method,route,status}`（histogram）
- `http_requests_total{method,route,status}`
- `ws_connections_active{}`
- `ws_messages_total{direction,type}`
- `chat_messages_sent_total{convType}`

**依赖：**

- `go get github.com/prometheus/client_golang/prometheus`

**验收：**

- `curl :8082/metrics` 返回 prometheus 文本
- docker-compose.observability.yml 起 prom + grafana → load dashboard.json → 看板显示流量
- 集成测试跑一发消息 → chat_messages_sent_total 加 1

### 批次 5（B3）：E2E 上 CI（3 天）

**新增文件：**

- `.github/workflows/e2e.yml`
- `apps/web/tests/README.md`（如何本地跑 + trace 复盘指引）
- `deploy/docker-compose.e2e.yml`（无卷持久化的一次性栈）

**关键流：**

- 登录 / 收发文本 / 撤回 / 图片消息 / 建群 / 群改名 / 好友申请（v0.2 A1 已加 delete/block）

**CI 步骤：**

1. `docker compose -f deploy/docker-compose.e2e.yml up -d --wait`
2. `go run ./cmd/seed && go run ./cmd/server &` （wait for :8080/health）
3. `pnpm --filter @yuanchat/web build` + preview
4. `pnpm --filter @yuanchat/web exec playwright test`
5. 失败 → `--trace on` artifact 上传

**验收：**

- PR + main 触发；4 分钟内跑完全部流
- 失败下载 trace 用 `pnpm exec playwright show-trace` 可视化
