> 路由: `/settings`

> 依赖：`DESIGN_LANGUAGE.md`

## 一、设计目标（Design Goals）

### 1.1 设置页要解决的核心问题

1. **可发现性**：用户能在 3 次点击内找到任意设置项
2. **即时预览**：外观设置（主题/字号/皮肤）实时预览，不用保存后再看
3. **安全明显**：危险操作（注销/退出所有设备）有明确的视觉隔离和二次确认
4. **企业扩展**：企业版额外的团队/权限/审计日志设置不影响个人版体验

### 1.2 与竞品差异化

| 竞品痛点                     | 元聊解法                                  |
| ---------------------------- | ----------------------------------------- |
| 微信设置全平铺，找项目靠滚动 | 分组卡片布局 + 导航侧边栏，快速定位       |
| 多数 IM 无密度/字号预览      | 实时预览气泡，所见即所得                  |
| 通知设置粒度粗               | 每个会话独立通知级别                      |
| 设备管理信息少               | 设备类型/IP/地理位置/最后活跃时间全量显示 |
| 无快捷键设置                 | 桌面端完整快捷键自定义                    |

## 七、状态规范

### 7.1 设置项加载状态

```
首次进入设置页: 骨架屏（分组卡片 + 每行 灰条）

```

### 7.2 设置保存状态

```
Toggle / 选项: 即时保存，无"保存按钮"
  成功: 无提示（静默）
  失败: Toggle 回弹 + Toast "保存失败，请重试"

表单类（修改昵称/密码）: 独立 [保存] 按钮
  保存中: 按钮 Loading
  成功: Toast success + 返回/关闭
  失败: 就地错误提示
```
